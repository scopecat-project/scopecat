# 维护者专项：不用 AI 完成备份和恢复

这是独立的维护练习，不要求普通实验作者和扫描题一起完成。只对**本版本新建的合成练习项目**
操作，不选择实验电脑上未经清点的真实数据。需要维护者提供同版本安装包、离线 wheel
目录和明确版本身份；未安装 AI 助手不影响这些步骤。

## 先认清三个位置

- 源项目：VS Code 当前打开、包含 `scopecat.toml` 的文件夹。
- 数据目录：通常是该文件夹里的 `.scopecat`；若有 `scopecat.runtime.toml`，按其中配置。
- 新输出目录：你选的空闲位置，必须尚不存在，并在源项目、数据和部署目录之外。

先完成一次合成测量，记下 run ID。在 VS Code 运行“停止实验服务”。打开项目的
PowerShell 终端，确认提示符所在目录。以下命令中的 `.` 就是当前目录；路径中有空格时
必须加引号，示例目录名可以换成自己的名称。

如果找不到程序，先用维护者提供的离线环境准备流程，不要下载随机版本补装。
若提示服务或写入者仍在运行，回到停止任务检查；不要删除锁文件来绕过。

## 创建并核验备份

以下命令在源项目的上一级创建 `backup-practice`，再验证其中的数据库和对象：

```powershell
.venv\Scripts\scopecat.exe snapshot create . "..\backup-practice"
.venv\Scripts\scopecat.exe snapshot verify "..\backup-practice"
```

原目录不被覆盖。检查成功消息，并记录源项目和备份两个真实路径。备份包含当前格式
的数据、源码和身份，但不包含可直接搬走使用的 `.venv`。

## 在新位置恢复并读回结果

选择另一个尚不存在的目录：

```powershell
.venv\Scripts\scopecat.exe snapshot restore "..\backup-practice" "..\restore-practice"
```

在 VS Code 打开 `restore-practice`。按同版本离线准备指南为这个新位置建立环境，
再选其 kernel；不要沿用旧项目的 editable 安装或旧内核别名。保持源项目服务停止，
用“启动实验服务”“打开实验界面”，在 History / Runs 找到已记下的 run ID，读取
原 IQ 和原分析，然后新增一个分析。新旧分析必须分开可见，不能只看文件夹出现。

恢复保留原身份和实验台所有权约束，不能让两个副本同时控制同一台，也不能把它们
作为共享采集编号的两个独立写入端。此处只启动合成项目，不授予真实设备执行许可。

## 版本边界

这项练习只验证**当前格式的备份恢复**，不是跨版本升级。schema 68–74 的开发迁移
演练与 migration 命令已退役；当前 schema 81 也不是长期兼容基线。新版本遇到不匹配
的数据会拒绝操作，不暗中改库。保留历史文件及匹配旧环境，新开发使用新数据位置，
不要为了启动而删除旧库或手工修改版本号。

教材环境准备只接纳匹配 build_id 的教学项目；本练习使用同版工具和教材。不要修改
身份文件绕过环境检查。副本期间新增的数据不会自动回灌原目录。

记录：是否能独立选对目录、理解命令效果、判断何时停服务、找到备份、读回原结果？
任何一步不能确定时，保留当前目录和错误信息即可；不要靠反复复制整段命令猜答案。
