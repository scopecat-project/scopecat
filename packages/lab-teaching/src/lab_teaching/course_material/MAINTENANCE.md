# 维护者专项：不用 AI 完成备份、迁移和恢复

这是独立的维护练习，不要求普通实验作者和扫描题一起完成。只对**新建合成练习项目**
操作，不选择实验电脑上未经清点的真实数据。需要维护者提供包含本指南的新安装包、
离线 wheel 目录和明确版本身份；未安装 AI 助手不影响这些步骤。

## 先认清三个位置

- 源项目：VS Code 当前打开、包含 `scopecat.toml` 的文件夹。
- 数据目录：通常是该文件夹里的 `.scopecat`；若有 `scopecat.runtime.toml`，按其中配置。
- 新输出目录：你选的空闲位置，必须尚不存在，并在源项目、数据和部署目录之外。

在 VS Code 运行“停止实验服务”。打开项目的 PowerShell 终端，先确认提示符所在目录，
再执行 `.venv\Scripts\scopecat.exe migration plan .`。这里 `.` 就是当前目录；
命令只展示版本和升级步骤，不执行实验。当前新项目可能显示 70→70、没有步骤，这是
正常的备份副本练习；68/69 的旧练习数据才需要真实升级，不要手工修改版本号制造旧库。

如果显示找不到程序，先用维护者提供的离线环境准备流程，不要下载随机版本补装。
若提示服务/写入者仍在运行，回到停止任务检查；不要删除锁文件来绕过。

## 生成可检查的副本

选择一个实际新目录。例如以下命令在源项目的上一级创建 `upgrade-practice`：

```powershell
.venv\Scripts\scopecat.exe migration copy . "..\upgrade-practice"
```

`upgrade-practice` 是本例选择的目录名，可以换成自己的名称；空格路径必须加引号。
原目录不被覆盖。成功时应明确显示原快照和升级工作区两个路径：

- `upgrade-practice\original`：保留原 schema 的可验证快照。
- `upgrade-practice\project`：迁移后的工作区和数据。

程序核对原表、对象内容和外部拥有的数组文件；失败时保留原数据，不发布半成品输出。
不要把“命令结束”当成通过：检查成功消息，并记录本次输入、输出两个真实路径。

## 在新位置读回结果

在 VS Code 打开输出的 `project` 文件夹。`.venv` 不在备份里：按离线准备指南为这个
新位置建立项目环境，再选其 kernel；不要沿用旧项目的 editable 安装或旧内核别名。
用“启动实验服务”“打开实验界面”，在 History / Runs 找到已记下的 run ID，读取
原 IQ 和原分析，然后新增一个分析。新旧分析必须分开可见。

迁移副本共用原实验台的所有权锁，不能让两个项目同时控制同一台。此处只启动合成项目，
不因此授予真实设备执行许可。

## 真正恢复原快照

停止副本服务。回到源项目的终端，用同一个工具验证备份，再恢复到另一个新目录：

```powershell
.venv\Scripts\scopecat.exe snapshot verify "..\upgrade-practice\original"
.venv\Scripts\scopecat.exe snapshot restore "..\upgrade-practice\original" "..\restore-practice"
```

恢复保持原 schema。原来是 68/69 时，用匹配的旧 reader，或对恢复目录再做一次受支持的
copy 升级；新版运行时不会暗中改库。恢复目录同样需要自己的离线环境。用记录的 run ID
读回原结果才算恢复验收，不能只看文件夹出现。

软件回退是旧软件配合旧快照，不是把新库降级。副本期间新增的数据不会自动回灌旧库。
当前框架只验证 68→69→70 这两条开发升级边；正式长期数据基线尚需明确指定。
本教材的 prepare 只接纳匹配 build_id 的教学项目，不承担旧教学包环境身份的升级；
本次练习用同版 70→70 副本验证维护步骤，旧包仍保留其环境，不修改身份文件绕过。
