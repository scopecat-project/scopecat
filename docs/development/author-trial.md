# 真人实验作者试用：三条短流程

本页对应 main 的 #1440（直接测量保留）和 #1441（对象与用途映射）。
面向会基本 Python、未实现这些功能的实验作者。全部使用隔离数据目录和公开 Virtual VNA；
没有真实接线或物理测量。**脚本代跑及组件检查不算真人独立试用。**

## 主持人准备

- 为本次试用建立独立应用数据目录、作者目录，记录 commit、系统、Python、应用启动方式。
  不替换日常安装，不复用正式数据或真实设备。
- 按[入门作者教程](../tutorials/starter-authoring.md)准备作者环境，并启用提供
  `scopecat.virtual.vna` 的驱动来源。界面名称为 **Virtual network analyzer**，连接为 `virtual`。
  只提供模拟来源；不要让参与者靠试连猜驱动。
- 记录哪些准备由主持人完成。若评估首次安装、目录创建或驱动启用，应另安排空白环境，
  不把预先完成的步骤计入作者独立成功。
- 先给参与者每节的「任务卡」，让其边做边说预期。下方「操作提示」按需提供；每次提供都记为帮助。
  不代填 capability、路由、代码或执行提交。可以随时停止；停下处也是有效观察。

## 一、借模拟 VNA 测量、保存、重开（约 10 分钟）

**任务卡：** 临时借用模拟 VNA 得到一条曲线，保存，结束控制并重开应用，找回同一结果。
说明你如何知道找回旧结果时没有再测一次。

**操作提示：**

1. 在设置保存操作者；**设备与驱动 → 添加设备**，选择 Virtual network analyzer 和 virtual 连接，
   命名为 `Trial Virtual VNA` 并保存。保存不自动采集。
2. 打开该设备的操作入口（桌面为 **打开控制窗口**），显式 **连接**。
   找到 Network sweep 的采集项，执行一次 **收集 Collect**。这是新扫描。
3. 在 **直接测量记录** 点击 **保存此结果**，勾选保存记录查看曲线与记录 ID。
   保存只保存已返回的回执；保存失败应重试保存，不重新采集。
4. **释放控制**，在 **结束直接控制** 中阅读收尾说明。本模拟练习选择 **保持当前状态并结束**；
   它不恢复进入前设置。没有完整关闭/归零配置时，相应选项不可用，不猜测收尾动作。
   如有未保存结果，先保存；只有确实不要时才明确放弃。
   正常退出并重开同一隔离应用，进入该设备的直接测量记录，勾选原记录。
   核对记录 ID、时间、坐标和曲线；查看旧记录不需要重新连接或 Collect。
5. 可选：重新连接，查看 **Read existing trace (no trigger)** 的说明。
   它读取仪器保留的曲线，不触发新扫描；刚启动或连接重建后可能没有已有曲线。
   不把这个错误当作要求自动扫描。当前仅公开虚拟 VNA 实现此能力。

**观察：** 是否能区分连接、采集、保存和重开；能否找到保存入口；未保存提示是否可理解；
退出后是否试图重新 Collect 才能找数据；是否把“释放控制”误解为恢复原设置或硬件关输出。

## 二、逐线换接、比较、备注、重测（约 15 分钟）

**任务卡：** 用同一模拟 VNA 记录 A、B 两条模拟线路，比较曲线，把 A 标记为可疑，重测 A。
保留 A 的第一次结果和说明。这里只模拟换线确认，不接触真实线缆。

**操作提示：**

1. 连接后填写 **线路名称** `A`、**测量备注**，勾选 **已人工确认当前接线为 A**。
   Collect 后 **保存此结果**。
2. 点击 **换到新线路**，填 `B` 并重新确认。此操作保持仪器设置不变，不自动测量。
   Collect 后保存 B。不要靠改名把 A 的历史变成 B。
3. 勾选 A、B 两条保存记录，逐项比较曲线、坐标、单位、时间及备注。
   比较不会自动重采样；相同的模拟响应也可能得到相同曲线，不据此声称真实线路相同。
4. 在 A 的已保存详情填写 **追加备注**，勾选 **标记异常**，点击 **追加标记（不修改原结果）**。
5. 点 A 的 **继续此线路（需确认接线）**，再次确认 A，Collect 并保存新尝试。
   核对三个不同记录 ID，A 的两个尝试及 B 都在，旧备注仍在。
6. 释放控制、重开同一应用，再比较三条记录。没有新的 Collect，也应能读到旧曲线和备注。

**观察：** 能否发现“换到新线路”与“继续此线路”的区别；确认框是否被当作自动检测接线；
是否误以为重测覆盖旧结果；能否找到异常备注与比较入口；旧记录的线路身份是否清楚。

此流程使用 #1440 的直接测量记录。另一入口「物理线路扫描」需要保存好的实验测量模板，
有独立的准备、提交与人工判断流程；不要把两套入口混在同一任务中。

## 三、从零映射对象与用途，修改 Python 并找回结果（约 20 分钟）

**任务卡：** 建立 q0 的模拟读出用途，绑定到 VNA，运行一个 51 点 Python 实验。
把源码的终止频率改为 5.2 GHz，再运行 101 点，最后找回第一次结果并说明两者差别。

**操作提示：**

1. 先释放手动控制。进入 **参数与绑定 → 实验 setup → 新建 setup**。
   填新名称 `trial-q0`；添加实验别名 `demo-vna`，选刚登记的模拟 VNA。
2. 在 **对象 → 用途 → 设备通道** 添加对象 `q0`（当前表单建立 `qubit`），
   添加用途 `demo-readout` 及说明“模拟 VNA 读出”。添加映射 `q0-readout`，选择 q0、该用途和 demo-vna。
   从设备声明核对能力 ID `scopecat.network_sweep/v1`；公开 Virtual VNA 在整机挂载，组件路径和逻辑通道留空。
   不把界面的示例 `channels/...` 当作此设备的通道。
3. 检查草稿提示并 **保存 setup**。本地映射检查不是可执行性证明；稍后仍须 prepare。
   若要改绑定，另存新名称并重新准备，旧运行保持原配置。
4. 按[设备到 Python 教程](../how-to/device-to-python.md)复制设备页实验声明至
   `src/scopecat_lab/authored/capture.py`。将其中选择资源的一行改为：

   ```python
   vna = network_sweep(experiment, for_=sc.one("q0", kind="qubit"), role="demo-readout")
   ```

   不运行该教程中替换 routing 的整段配置代码，它是另一种无实体示例。
   沿用已准备的作者参数分支，在 Notebook 连接原应用后刷新、选择刚保存的 setup：

   ```python
   author.refresh()
   from scopecat_lab.authored.capture import capture
   from scopecat_lab.authored.parameters import open_parameters

   params = open_parameters(author)
   author.use(setup=author.setup.get("trial-q0").ref)
   request = capture(points=51)
   prepared = author.prepare(request, parameters=params)
   print(prepared.preview)
   ```

5. 核对预览后另行提交：`job = prepared.run()`，
   `run = job.wait(timeout=120).result()`，记录 `job.receipt` 和 `run.id`。
   GUI **数据** 查看该运行。准备和保存配置不采集，提交才采集。
6. 在 capture.py 将 `stop_frequency=sc.Quantity(5.1, "GHz")` 改成 `5.2`。
   保存，`author.refresh()`，重新 import capture，创建 `capture(points=101)`，重新 prepare、核对并 run。
   保存第二个 receipt 和运行 ID。只改旧 request 不会改变已有 prepared。
7. `author.close()`，正常重开原应用与 Notebook，只运行连接和重开单元格：

   ```python
   from pathlib import Path
   original = author.reopen(Path("第一次打印的 receipt 路径")).wait(timeout=120).result()
   print(original.id, original.measurements()["frequency"].require_magnitudes("GHz"))
   ```

   第一次仍为 51 点、终止 5.1 GHz；第二次为 101 点、终止 5.2 GHz。不要 Run All 或重新提交来找回结果。
   超时继续等待同一个 job；提交结果不确定时按教程用原 receipt 恢复。

**观察：** 能否解释登记设备、别名、对象、用途的差别；精确 capability ID 与路径需要多少帮助；
错误映射能否按提示修复；是否知道刷新后重新 import 和 prepare；能否区分当前源码与旧运行来源。
