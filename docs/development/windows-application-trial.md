# Windows 应用体验验收

这是普通用户入口与更新恢复验收，不涉及真实设备或历史数据迁移。
维护者先提供明确的 Windows 交付、commit/构建编号、Python ABI 和自动检查结果。
PR 合并或快速 CI 通过不能替代真人观察。

## PR 2 本轮需要的人工抽查

下面是一段连贯的 Windows 原生体验，不是要求重走整份历史验收指南。
PR 1 已确认且本轮未修改的安装、升级和作者环境体验继续有效。

1. 安装新包并打开，再次打开入口，确认没有额外后台或终端窗口。
2. 两个窗口分别打开不同文件；检查切换、最小化、关闭额外窗口，以及
   从托盘隐藏全部窗口后再次打开应恢复全部保留窗口；关闭最后一个窗口后也应
   能从托盘恢复。已经关闭的额外窗口不应重新出现。各窗口的记录和比例应保持独立。
3. 在中文空格路径使用原生打开和保存对话框，分别取消一次。
   快速检查复制到记事本、查找、缩放，以及一份波形是否正确显示。
4. 在文件操作确实尚未结束时，检查等待退出和停止退出；重新打开后确认
   可操作，原文件没有被半成品覆盖。如果文件太小而无法观察，就记为未覆盖，
   不要反复人工制造延时；由维护者提供可观察的样本。

科学引用完整性、冲突、独立分析、逐条释放数组、清理重试和取消后的文件完整性
由自动化覆盖。Windows 对打开中文件的删除限制由 native-distribution 中的真实
文件句柄测试覆盖，不要求操作者修改权限或锁文件。Mac 已记录的失败恢复不再
要求 Windows 人工照搬；只有 Windows 实际出现的平台差异才增加针对性观察。

下面的详细步骤用于定位问题或相关功能变更时复查，并非每次构建全部重验。

## 安装与打开

使用维护者提供的原生 Setup 安装包，选择新的中文空格路径。不预装 Python 或 uv。
作者代码体验另需 VS Code 的 Python/Jupyter 扩展。

从开始菜单打开 **Scopecat**。预期直接进入工作台，没有实验室选择页、管理页、
额外浏览器或需要保留的黑色终端。再次双击应激活同一个窗口。
记录首次打开时间、是否有错误及重复窗口；不要仅凭重试成功忽略首次失败。

## 日常代码与退出

1. 打开 Settings，点击 **New code folder**，选择保存位置并创建示例。
   先取消一次目录选择，确认应用仍可操作；再次选择新的中文空格目录。
   创建完成后应回到 Settings，显示该目录和它自己的 `.venv`。
2. 用 VS Code 直接打开此目录，选择 `.venv` 中的 Python 作为内核，
   逐段运行 `notebooks/02_edit_scan.py`。确认三点合成实验及分析结果可见。
3. 从系统托盘选择隐藏窗口，再从托盘打开。重复双击开始菜单入口，
   应回到同一个应用和记录，不新增窗口或重新采集。
4. 关闭窗口应隐藏到托盘，后台继续运行；从托盘打开应恢复同一窗口。
   从托盘明确选择退出时，空闲应用应直接退出；检查和停止期间应立即显示进度。
   重新打开仍应保留记录，VS Code 中的作者 Python 仍可使用。
5. Help 与 Settings 在当前工作台内打开，不跳转到管理页面。

另检查窗口状态组合：先最小化，再从托盘选择隐藏，随后选择打开；窗口应
恢复到可见、可操作状态。重复隐藏/打开以及从开始菜单再次启动，都应回到
同一个应用，而不是创建另一份后台。

### 有任务时的关闭

在上述可丢弃示例的 `src/scopecat_lab/authored/signal.py` 中，临时给
`response` 函数增加 `time.sleep(30)`，并添加 `import time`。
重新运行示例的 refresh、prepare 和 run 段，等工作台显示 **Running** 后再关闭窗口，
确认任务继续执行。从托盘重新打开，再从托盘选择 **退出 Scopecat** 检查以下选项。
仅启动 Notebook 或开始导入 Python 不能证明已有后台任务。

- 选择 **Keep running in background**，从托盘重新打开，确认界面可以继续操作，
  同一任务仍在运行或已正常完成。
- 再次从托盘选择退出，选择 **Cancel**，确认仍可查看任务。
- 选择 **Quit when work finishes**，确认任务完成后应用和托盘退出；
  重新打开后核对三点结果与分析，不重新提交。
- 另开一次合成任务，选择 **Stop and close**，确认退出，重新打开可查看停止状态，
  没有假报完成或自动再次采集。

完成后移除临时延时。记录各选项结果；不要用空闲时关闭替代运行中关闭验收。
全程不连接真实设备。

## 数据窗口与基础操作（PR 2）

Mac 与 Windows 使用相同的关闭规则：关闭额外窗口只关闭该视图；关闭最后一个
窗口隐藏到菜单栏／托盘，空闲和有任务时都保留应用。重新打开应恢复保留的视图。
只有明确选择 Quit 才发起应用退出，不因空闲自动退出。

使用维护者提供的两个不同 `.scopecat` 文件，分别在两个窗口打开。
在前一个窗口操作，确认后一个窗口的记录、导航与比例不变。
数据窗口标题应包含记录 ID 和来源；通过系统窗口切换入口确认能分别找到两份
记录。Mac 的“窗口”菜单应列出真实数据窗口，关闭后及时移除对应条目，
不应出现托盘等内部辅助窗口。

| 操作 | 快捷键 | 预期 |
| --- | --- | --- |
| 打开文件 | Ctrl+O | 原生选择框；取消后保留当前记录 |
| 查找当前视图 | Ctrl+F | 搜索可见标题或记录 ID；Enter 查下一个，Shift+Enter 查上一个 |
| 关闭查找 | Escape | 返回原控制项；不存在的文本明确显示 No matches |
| 放大／缩小 | Ctrl+Plus / Ctrl+Minus | 文字、表格和图表仍可读且可操作 |
| 实际大小 | Ctrl+0 | 恢复 100% |

上述操作也应能从文件／视图菜单找到。Mac 上将 Ctrl 换成 Cmd。
特别检查 Windows 快捷键是否被 WebView 自身拦截，以及 Mac 匹配文字是否
实际高亮并滚动到视区；只看到“Match found”不算通过。

### 复制、导出与独立分析

1. 选中完整记录 ID，用 Ctrl+C 复制到记事本，核对文本完全一致。
   再打开维护者提供的无效文件，复制错误文字；原记录应仍可查看。
2. 在 Data 选择 **Save a copy…**，先取消一次，再保存到新的中文空格路径。
   等待保存路径确认，用另一个窗口打开副本，核对记录、测量值与分析。
   在 Experiments 对合成实验使用 **Export Scopecat file…**，同样核对结果。
3. 按[普通 Python 分析](../guides/ordinary-analysis.md#analyze-an-exported-file-in-your-own-python-environment)
   使用独立 Python 环境分析导出的文件，将结论写入新的文件，再从应用打开。
   原测量与新结论应同时可见，不应要求连接设备、安装 private 适配或重新执行实验。
4. 用维护者提供的大波形样本，切换采集历史与保留的分析选点，再切换波形记录。
   核对点编号、单位和数值摘要随选择更新；绘图应说明采样显示，应用仍能操作。

失败恢复已有自动化及 Mac 原生观察。Windows 本轮以自动化验证业务结果，
人工检查原生控件是否保持可用；遇到 Windows 特有故障时再记录并补对应回归。

## 更新与恢复

结束任务并退出应用，安装维护者提供的第二个明确版本。
重新打开原来的快捷方式，应使用新安装版本；源码和已保存记录保留。
核对作者 Python 仍可使用，应用更新不会自动替换用户环境。

没有提供版本对时，将升级记为“未尝试”；同包重装不算版本升级验收。
失败时保留原产物和诊断，修正后重试。不删除数据库或锁文件。

维护者可在可丢弃安装中进行受控的进程强制结束试验。后续重开或复检应识别有效残留；
错误解释器应仍能显式停止。不要要求普通用户在任务管理器里按名称猜测要结束哪个 Python。
独立开发 home 的停止不能影响另一个 home。

## 反馈与证据

提供 Windows 版本、实际安装路径、commit/构建编号及各步结果。
记录等待时间、不明确的按钮和错误文字。失败时附应用数据目录的
`native-start.log`、`desktop/desktop.log`，并说明原快捷方式能否重开。
默认应用数据目录为 `%LOCALAPPDATA%\Scopecat`；使用隔离验收目录时以
Settings 显示的 Application home 为准。不要为了取得日志额外启动命令行服务。

教学 CLI 仍保留隔离练习环境；同服务创建和清理练习属于后续批次，
本轮不声称该能力已完成。Windows 间歇启动/端点丢失问题仍需对应失败证据；
成功的一次体验不能代替根因修复。软件检查、真人观察和物理设备验收分别记录。
