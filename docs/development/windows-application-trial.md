# Windows 本地应用小范围体验

这是 [#616](https://github.com/scopecat-project/scopecat/issues/616) 的安装和日常入口体验，
不需要重做已经体验过的参数、compute 教程，也不需要 AI 助手、源码仓库、Node 或本地构建。
请使用新的、可丢弃的应用目录和模拟练习；这轮不涉及真实仪器或历史数据升级。

## 开始前：等待明确的交付版本

本轮交付由 [#668](https://github.com/scopecat-project/scopecat/issues/668) 追踪。
手动 **Full acceptance** 工作流的 `local-application` 模式检查安装和浏览器流程，
不等于完整验收。不要直接下载一个不明确的“最新版”。维护者应先提供：

| 内容 | 应收到的信息 |
|---|---|
| 下载 | 成功的公开 Actions 运行链接及 `scopecat-tutorial-windows-latest` 附件 |
| 版本 | commit、交付包构建标识、操作系统/CPU/Python ABI |
| 自动检查 | Windows/Linux 结果，以及失败或尚未执行的项目 |
| 升级版本对 | 如需检查版本升级，提供两个明确、可信的交付版本 |

目前这里尚未记录实际运行链接和版本；PR 合并或快速 CI 通过不能替代安装验收。
Actions 附件会过期，验收通过的交付包需另行保存。

解压 Windows 附件后，`tutorial.zip` 是完整交付包，`tutorial-evidence/` 是自动检查报告。
再解压其中的 `tutorial.zip`，安装文件在第二次解压得到的 `tutorial/` 中。
交付目录中应有 `install.py`、manifest 和全部安装文件，请保持目录完整。
电脑需要匹配的 Python 3.14 和 uv；打开教学 Notebook 还需要 VS Code 及 Python/Jupyter 扩展。
如果版本、附件或前置软件不明确，反馈缺少的内容即可，不必自己重新构建。

## 1. 安装到容易辨认的目录

选一个新的体验目录，名称包含空格和中文，例如 `D:\Scopecat 体验`，使用电脑上实际存在的盘符。
在资源管理器中打开解压后的交付目录，选择 **在终端中打开**，运行：

```powershell
python install.py --home "D:\Scopecat 体验"
```

引号内是你选择的应用安装目录，不是下载解压目录。把它改成实际路径并记下来。
安装只需要这一条命令，程序自行管理版本子目录；不需要激活环境或手动给文件夹编号。
保留安装结束时显示的信息，尤其是所选版本标识。
如果 `python` 打开应用商店或使用了其他 Python 版本，先反馈这个前置软件问题。

## 2. 双击打开，再次打开

进入刚才的安装目录，双击 `lab.cmd`。预期打开本地管理页：主界面是实验服务，教学位于帮助区。
新的目录中可以没有已注册服务。关闭浏览器标签，再次双击同一个 `lab.cmd`，
检查是否能重新进入，而不需要选择端口、环境或项目编号。
如果遇到 Windows 提示、终端一闪而过、重复页面或不知道该等多久，请记录下来；重试成功也值得反馈。

展开 **帮助 · 教学与练习**，打开一个已经熟悉的专题，确认准备好的文件夹在 VS Code 中打开。
不必重做课程或修改实验代码。关闭 Notebook kernel，在专题卡片中停止练习服务，
然后重新打开管理页，确认练习副本和操作历史仍然可见。本步不需要重置或删除副本。

## 3. 安装到同一个目录

从同一个交付目录再次运行原来的安装命令。重新打开原来的 `lab.cmd`，
已有练习副本和操作历史应继续保留，也不应要求重新构建 GUI 或另建应用目录。

只有在维护者提供了明确的升级版本对时，才进行下一步：等待管理操作结束，
从第二个交付目录安装到同一个应用目录，再打开原来的启动器，记录新选择的版本标识。
旧练习副本仍使用自己的原有环境。管理器升级不会更新已注册实验服务的环境，
不要把管理器版本变化理解为所有实验服务都升级了。
没有提供版本对时，将“版本升级”记为 **未尝试**；同包重装不算升级验证。

如果交付中明确提供了虚拟实验服务，再体验：
**停止服务 → 重新检查环境 → 启动 / 检查工作台**。
重新检查后服务应仍处于停止状态，服务编号不变；打开工作台后，原来的管理页应仍然可用。
从工作台进入 **Help and maintenance**，判断是否能看懂已注册的项目、Python 和 GUI 路径。
如果没有提供虚拟服务，将这一步记为 **未尝试**，不用自行注册项目，也不要用真实仪器项目代替。

## 怎样反馈

提供 commit/构建标识、Windows 版本、实际安装路径，以及各步的简短结果。
如果某一步不知道要等多久，请记录等待时间；如果某个名称或路径不直观，请指出具体位置。
成功步骤用几句话或截图说明即可，不需要填写 JSON，也不需要整理完整命令记录。

发生失败时，保留错误文字、截图和管理页提供的操作日志，并说明原来的启动器是否仍能打开。
安装失败或浏览器打开前失败，则保留终端输出。
不要为了消除错误而删除应用目录、失败的运行环境或下载包，也不必反复重试不明原因的失败。
分享日志前可隐去本机敏感信息；需要进一步定位时，维护者会给出具体的小任务。

自动软件检查、这轮真人观察和以后的真实仪器验证分别记录。
本轮通过不代表已建立持久数据兼容基线。
