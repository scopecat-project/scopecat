# Windows 应用体验验收

这是普通用户入口与更新恢复验收，不涉及真实设备或历史数据迁移。
维护者先提供明确的 Windows 交付、commit/构建编号、Python ABI 和自动检查结果。
PR 合并或快速 CI 通过不能替代真人观察。

## 安装与打开

准备匹配的 Python 3.14、uv，以及 VS Code 的 Python/Jupyter 扩展。
从完整交付目录安装到新的中文空格路径：

```powershell
python install.py --home "D:\Scopecat 体验"
```

双击安装目录内 **Scopecat.lnk**。预期直接进入工作台，没有实验室选择页、管理页、
额外浏览器或需要保留的黑色终端。再次双击应激活同一个窗口。
记录首次打开时间、是否有错误及重复窗口；不要仅凭重试成功忽略首次失败。

## 日常代码与退出

由维护者提供一个已登记的合成作者目录：

1. 用 VS Code 直接打开目录，选择 Settings 中显示的 Python 解释器作为内核。
2. 预览并提交一次合成实验，在工作台查看同一记录。
3. 关闭窗口选择后台运行，重新打开后应看到原记录，且不会自动再采集。
4. 结束工作、关闭内核，关闭窗口选择停止。重新打开仍应保留记录。
5. Help 与 Settings 在当前工作台内打开，不跳转到管理页面。

只读数据不要求连接设备。若交付没有作者示例，记录此项未提供，不使用真实台架替代。

## 更新与恢复

先在 Settings 准备维护者提供的第二个明确版本。准备过程中原应用仍可用；
候选未核验通过前不能切换。结束任务、关闭内核后明确停止并应用候选。
重新打开原来的快捷方式，应使用同一个选定版本；源码和已保存记录保留。
核对 VS Code 内核已改为新解释器。

没有提供版本对时，将升级记为“未尝试”；同包重装不算版本升级验收。
失败时保留原产物，修正后重试相同候选。不删除数据库或锁文件。

维护者可在可丢弃安装中进行受控的进程强制结束试验。后续重开或复检应识别有效残留；
错误解释器应仍能显式停止。不要要求普通用户在任务管理器里按名称猜测要结束哪个 Python。
独立开发 home 的停止不能影响另一个 home。
